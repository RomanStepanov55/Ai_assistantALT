# Изменения — SkillBotRobloxMuscle

## v1.5 — 2026-11-17

**Тема: живая тренировка с подтверждённым приростом и приложение «Алонтито».**

### Измерено вживую

- Сила **3.12M → ~5.39M** за сессию; гемы **16.1M** без единой траты.
- Темп: 6 повторов — 16 358/мин; 20 повторов — 124 598/мин и **155 998/мин**
  (+660 000 за 253.8 с, подтверждены 3 из 4 подходов).
- 42/42 живых кадров игры дали плашку силы.

### Исправлено

1. **Одно событие — одно число** (`games/muscle_legends.py`).
   Внешний замер вокруг подхода дал `-438,100` там, где `smart_lift` подтвердил
   `+78,900`. Для подходов `metrics_delta["strength"]` теперь берётся только из
   подтверждения, второе чтение не делается (E-013).
2. **Слот 2 — переключатель, а не «экипировать»** (`agent_actions.smart_lift`).
   Состояние выводится из подтверждённых приростов; нажатие только при
   неподтверждённой экипировке (E-014, EXP-07).
3. **Приглашение на бражл отклоняется** через NO (`handle_popups`): окно
   перекрывает клики и съедало подходы (E-015, EXP-08).
4. **Страница клиента — не игровое поле** (`vision/template_reader.py`,
   `games/muscle_legends.py`). Плашка бейджа должна содержать чернила цифр;
   `execute_action` и `smart_lift` получили жёсткий гейт по `frame_is_game`
   (E-016, EXP-09).
5. **Ведущая цифра гемов не теряется молча** (`read_gems`): нужны два
   согласованных кадра, иначе `None` (E-017).
6. **`modal_open` без слов из мира**: `join` и `trade` убраны из управляющих
   слов (E-018).

### Новое приложение

- `alontito/` — `ui` (ANSI в стиле макета), `memory` (9 статусов, навыки,
  прогоны, журнал), `games_catalog` (Place ID, `roblox://placeId=`, ожидание
  HUD), `skills` (`TRAIN_DUMBBELLS` + `CLOSE_MODAL`), `brain` (план → замер →
  рефлексия → одно улучшение), `app` (REPL).
- Вход: `python alontito.py` или `Alontito.bat`.
- 18 команд, включая `/play`, `/auto`, `/attach`, `/status`, `/train`, `/watch`,
  `/learn`, `/memory`, `/skills`, `/journal`, `/safety`.

### Автопоиск при запуске (v1.1.0)

После старта приложение само находит Roblox, определяет плейс и открывает нужную
игру — без ручных шагов:

1. **Окно уже есть и игра идёт** → подключается, ничего не перезапускает.
2. **Окно есть, но это страницы клиента** (после сессии клиент показывает музыку,
   аватар и т.п.) → открывает нужный плейс через `roblox://placeId=`.
3. **Ничего не запущено** → запускает выбранную игру (по умолчанию Muscle Legends,
   place 3623096087) и ждёт HUD.

Идентификация — по `placeid:` из собственного лога клиента
(`%LOCALAPPDATA%\Roblox\logs`), свежесть лога ограничена 6 часами. Если лог
отсутствует, приложение так и пишет: «HUD виден, но какой именно плейс — не
доказано» — имя окна доказательством не считается. Если открытый плейс не совпал
с запрошенным, это выводится отдельной ошибкой.

Управление: `/auto` — состояние, `/auto on|off`, `/auto now` — найти сейчас.
Настройка хранится в `data/alontito/memory.json`.

## v1.4 — 2026-11-16

**Тема: живая сессия; глаз не выдаёт число из чужого окна и не называет сцену модалкой.**

### Проверено вживую (только чтение)

- Игра запущена: `RobloxPlayerBeta.exe` PID 28160, окно `Roblox`, клиент 1920×1046, DPI 150%.
- Place ID доказан логом самого клиента: `placeid:3623096087`, `universeid:1268927906`.
- Сила **3.11M** (conf 0.957), гемы **16.1M** (conf 0.967); три независимых кадра совпали, `--health` → `ok`.
- Захват 170–256 мс, чтение 700–835 мс.

### Исправлено

1. **`"00"` больше не число** (`vision/template_reader.py`).
   `--health` выдавал силу `0` (conf 0.70) из кадра с окном терминала: OCR-rescue читал любой текст, а формат принимал ведущие нули. HUD ведущих нулей не печатает → отказ.
2. **OCR-rescue требует бейдж в кадре** (`Eye.read_once`).
3. **`self_check` без HUD сразу возвращает `blind`** и `null`, не читая ничего.
4. **`modal_open` доказывается управляющим словом** (`vision/eye.py`: `dialog_word`, `_DIALOG_WORDS`).
   Правило «3+ строки OCR = модалка» давало **36 из 46** кадров, включая окно самого агента; политика считает модалку срочной и кликала слепую координату «закрыть». Теперь нужны управляющее слово (`YES/NO/CLAIM/…`, нечёткое сравнение) **и** HUD этой игры в том же кадре.

## v1.3 — 2026-11-16

**Тема: честная классификация кадра и «крупная плашка = бейдж».**

### Исправлено

1. **Сохранённая раскладка больше не доказывает, что кадр — игра** (`vision/eye.py`).
   Домашняя страница приложения Roblox имеет тот же размер клиента, что игровое окно. Раньше она получала статус игрового кадра, а затем её пустые счётчики описывались как «нечитаемые» — неверное утверждение о том, что глаз видел.
   Теперь доказательство — только бейджи, найденные в текущем кадре (`_locate`).
2. **Минимальный размер плашки** (`Eye._locate`).
   Цветовая локация принимала за «гемы» зелёную кнопку 72×28 px в окне редактора. Плашка бейджа — крупный элемент (≥6% ширины и ≥3% высоты кадра); мелкие яркие элементы отбрасываются.
3. **OCR-rescue только при найденных бейджах** (`Eye.observe`).
   Раньше спасение OCR запускалось по кэшированной раскладке и тратило секунды на кадрах без игры. Время скана корпуса: 144 с → 23 с.
4. **Текст предупреждения уточнён**: «HUD not found … это приложение/Home Roblox или загрузочный экран …».

### Результат скана корпуса (48 кадров)

|---|---|---|---|---|
| v1.1 | 38 | 1 | 6 | 3 |
| v1.3 | 39 | 1 | 0 | 8 |

Оба читаемых кадра не потеряны; все бывшие «нечитаемые» оказались кадрами без игрового HUD.

### Тесты

## v1.2 — 2026-11-16

**Тема: чистое чтение бейджа, независимое от иконки, и адаптивная бинаризация.**

### Исправлено

1. **Иконка бейджа исключается единой сегментацией** (`TemplateReader._segments` / `_icon_indices`), которая используется и чтением, и обучением. Раньше «?» от иконки попадал в строку и ломал выравнивание глифов при обучении.
2. **Адаптивная бинаризация (Otsu)** для силы и для обоих вариантов второго бейджа: модалки затемняют сцену, абсолютные пороги слепли.
3. **Ширина кропа гемов 1.10×** — суффикс больше не отрезается (`14.0M` вместо `14.0`).
4. **Чистый OCR по маске чернил** (`ink_to_image`, `OCREngine.read_badge_number`): `2.76М` → `2.76M`, `14.ом` → `14.0M`.
5. **Производительность**: `_components` векторизован; `_remove_border_ink` переписан через RLE + union-find (в 7 раз быстрее, попиксельно идентично); ранний выход по маскам; мемоизация `_locate` на кадр.
6. **Глаз** (`vision/eye.py`): самокалибровка, кандидаты, временной консенсус, OCR-спасение с самообучением, `observe()`, `annotate()`, `glyph_health()`, `self_check()`, `frame_is_game()`.
7. **CLI** `eye.py`: `--health`, `--frame`, `--scan`, `--watch`, `--deep`; отчёт `debug_frames/eye_report.json`, галерея `debug_frames/eye_gallery.html`.

### Аудит глифов

65 читаемых глифов, 13 согласий с OCR-якорем. Подозрительная «4» оказалась легитимным вторым начертанием. Отсутствующее начертание выучено с живого кадра: `14.0M`, уверенность 0.98.
