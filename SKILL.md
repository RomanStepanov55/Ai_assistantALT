# Muscle Legends Autonomous AI Agent Skill

> Полная база знаний агента: **KNOWLEDGE.md** (Windows/ввод/DPI, зрение,
> механики игры, саморазвитие, отладочный плейбук). Этот SKILL.md — краткая
> выжимка; при конфликте приоритет у KNOWLEDGE.md.

Полный навык автономной игры в Roblox: Muscle Legends. Составлен по живой сессии
05-06.11.2026 (калибровка на 1920x1080, DPI 150%, окно развёрнуто на весь экран).

## 0. GOLDEN RULE (высший приоритет, зашит в код на трёх уровнях)
- **НИКОГДА** ничего не покупать за реальные деньги; не привязывать карты; не включать биллинги.
- **НИКОГДА** не принимать трейды (всегда Reject), не добавлять незнакомцев в друзья, не тратить предметы/бусты (диалоги "Use your X?" -> NO).
- Запрещённые кнопки: STORE, PACKS, SPOOKY PASS, Auto Lift (геймпасс), CODES, BENEFITS, TRADE, CLANS, MOVES.
- Защита: `config.ALLOWED_CLICK_ROIS` — whitelist ROI (всё вне списка отклоняется); `agent_actions.SAFE_BUTTON_WORDS` — клик внутри модалок только по текстам Collect/Claim/Spin/Rebirth/X/Reject/No; `handle_popups()` — торговые офферы всегда Reject; квест-Collect нажимается ТОЛЬКО если прогресс выполнен (защита от "Collect за 99 гемов").
- Мониторинг трат: `claim_gifts` и любые действия с валютой логируют дельту гемов; отрицательная дельта = тревога.

## 1. Запуск
```bash
python main.py              # полный автономный цикл (тренировки + подарки + квесты + колесо + ребёрн)
python main.py --monitor    # живой HUD-монитор
python main.py --watch      # фоновый глаз (только чтение): data/scene_state.json + data/eye_journal.log
python main.py --test-input # проверка ввода
python run_action.py --hud|--strength|--gift|--quests|--wheel|--rebirth|--observe|--close-modal
```
Телеметрия: `data/telemetry.log`. Журнал сцены: `data/eye_journal.log`. Память: `data/memory.json`.

## 2. Окно и экран ( критические уроки )
- Процесс бота обязан быть **DPI-aware** (config.py: PER_MONITOR_AWARE_V2), иначе захват режет экран, а клики смещаются.
- Кнопки могут остаться на **другом виртуальном столе** -> в ensure_focused лестница: ALT+SetForegroundWindow -> **SW_MINIMIZE+SW_RESTORE+SW_MAXIMIZE** (перетаскивает окно на текущий стол и разворачивает) -> AttachThreadInput -> SwitchToThisWindow.
- Окно должно быть **развёрнуто** (SW_MAXIMIZE) — ROIs калиброваны под развёрнутое окно 1920x1050 (клиент).
- Захват экрана (ImageGrab) видит то, что СВЕРХУ: перед чтением поднимать игру (ensure_focused).
- **ESC никогда не нажимать** (открывает системное меню Roblox). Окна закрывать крестиком/повторным кликом.

## 3. Зрение
- Верхний HUD: жёлтый бейдж = сила, второй бейдж = конфеты (зелёный, главный зал) ИЛИ гемы (синий, арены/ивенты) — авто-определение варианта по цвету фона (B>G -> синий).
- **Шаблонный ридер цифр** (vision/template_reader.py): шрифт бейджей фиксированный; эталоны глифов в data/glyph_templates.npz; нормализация 24x32, скоринг IoU, аутолин с жёлтого бейджа при посимвольном согласии с WinRT OCR (расхождения только на '?').
  - Бинаризация **адаптивная (Otsu)**: модалки затемняют сцену, абсолютные пороги слепли. Сила — Otsu по L (+ фиксированный порог как вторая независимая попытка); конфеты — Otsu по R−G (оранжевые цифры); гемы — Otsu по L (тёмные цифры на светло-синем).
  - Иконка плашки (гантель/гем) исключается единой сегментацией `_segments`/`_icon_indices` — и при чтении, и при обучении. Иначе `'?91.5K'` и сдвиг выравнивания глифов.
  - WinRT OCR (vision/win_ocr.ps1, JSON + боксы линий): читает силу/тексты, НО НЕ читает стилизованные цифры зелёного бейджа; выдаёт кириллические омоглифы ('СИАМ' вместо CLAIM) — везде fuzzy-сверка.
- **Слой глаза** `vision/eye.py` — единственный публичный продукт восприятия (`observe()`): самокалибровка по кадру, кандидаты боксов, временной консенсус, OCR-спасение с самообучением, `annotate()`, `glyph_health()`, `self_check()`.
  - CLI: `python eye.py --health` (живая проверка), `--frame PNG` (один кадр, оффлайн), `--scan` (весь корпус → JSON + HTML-галерея), `--watch`, `--deep`.
  - **Гейт «это игра?»**: доказательство — только бейджи, найденные в ТЕКУЩЕМ кадре (крупная плашка ≥6% ширины и ≥3% высоты). Сохранённая раскладка того же размера — не доказательство (домашняя страница Roblox совпадает по размеру). Кадр без бейджей → «без HUD игры», а не «нечитаемый счётчик».
  - Замер на корпусе 48 кадров (v1.3): 39 оба читаются / 1 частично / 0 нечитаемых / 8 без HUD; скан 23 с.
- **Sanity-гейт**: значения бейджей принимаются только в пределах x0.2..x5 от последних известных (анимации бейджа дают мусор).
- Watcher (brain/watcher.py): каждые ~10-20с пишет scene_state.json + журнал: сила/гемы/CLAIM/модалки/события (brawl, boss, raid, event). События видны в баннере под HUD ("Brawl starting in N...", "EPIC BOSS", "Strongbloxian Games", "NEXT BOSS SPAWNS IN").

## 4. Ввод и тренировки
- DirectInput scancodes (SendInput): слоты 1-0, E (встать за снаряд), SPACE (спрыгнуть/прыжок), W (бег), TAB (лидерборд), F11 (фуллскрин).
- Темп: анимация повтора ~0.65с — клики быстрее игнорируются.
- **Ловушка тренажёра**: клик по центру рядом со снарядом САДИТ персонажа на скамью (+11..12 силы за повтор — невидимо на фоне сотен тысяч!), режим тренажёра глотает UI-клики. Лечение: `smart_lift()` — замер силы до/после подхода; нет прироста -> SPACE + отход (S 1.3с) + повтор (до 3 попыток).
- Курсор перед подходом ставится в безопасный центр (CURSOR_SAFE_POINT), чтобы репы не попадали по HUD.

## 5. Попапы (handle_popups, вызывается каждые ~12с и перед каждым действием)
- Trade offer -> **Reject** (никогда Trade!).
- Friend request -> NO. Use your X? (бусты/шейки) -> NO. Карточка игрока -> клик в пустоту.
- Brawl "want to join?" -> игнорировать (истекает само; тренировки продолжаются и в арене).
- Любые YES на офферах — запрещены.

## 6. Игровые механики

> **Статус:** строки ниже — записи ранних сессий (06.11). Часть из них **не
> перепроверена** по корпусу 15–16.11 и не имеет подтверждающего кадра или
> официального источника (пороги залов, награда подарка, порог ребёрна, слоты
> 1..0). Считать их ГИПОТЕЗОЙ до записи в `knowledge/sources.csv` со статусом
> ПОДТВЕРЖДЕНО ИНТЕРФЕЙСОМ. Текущая база: `knowledge/mechanics.md`,
> `knowledge/economy.csv`, `knowledge/rebirth.md`, `knowledge/locations.csv`,
> `knowledge/equipment.csv`.

- Timed gift (справа, таймер ~3 мин): по готовности показывает CLAIM; **клеймится мгновенно одним кликом по боксу** (модалка не открывается); награда ~+2M гемов. Верификация: дельта гемов до/после.
- Quests: выполненные квесты (прогресс "N/M" с N>=M) -> Collect; невыполненные не трогать (кнопка Collect у невыполненного = покупка пропуска за гемы!).
- Wheel: клик WHEEL -> OCR "SPIN" -> клик -> 4.5с -> закрыть крестиком.
- Rebirth: порог растёт экспоненциально; у аккаунта **37 ребёрнов** (сверено с лидербордом TAB) — порог ~78 млрд, авто-ребёрн не сработает и не должен. Счётчик в data/memory.json (rebirths_known). Само действие REBIRTH **не нажимается** (необратимый сброс).
- Залы: Starter -> Frost (1 ребёрн, 10K) -> Mythical (3, 100K, x4) -> Eternal (5, 1M) -> Legend (10, 5M) -> Muscle King (30, 50M).
- События: Brawl (арена, телепорт, гемы-бейдж), EPIC BOSS, Strongbloxian Games — watcher журналирует, тренировки продолжаются в любом состоянии.

## 7. Известные ограничения / следующие шаги
- Глиф '0' **выучен** 15.11 через `tools/harvest_glyphs.py`; отсутствуют только B и T (на текущих силах не встречаются). Пополнение: `python tools/harvest_glyphs.py --write`.
- Синий гемовый бейдж в аренах иногда меняет цифры быстрее, чем читается — sanity-гейт держит последнее валидное.
- Модуль LearningMemory подключён (сессии, ребёрны), но `update_efficiency()` **никем не вызывается** — ротация тренировок по эффективности не работает (см. BUILDER_LOG.md, эксперимент E-002).
- Боссы/рейды: watcher видит анонсы; боёвая логика (подойти+атака) — следующий этап.
- Тонкая настройка: горячий путь (`read_strength`) держим без PowerShell; OCR-сервер используется только в детекторе и модалках.

## 8. Критические уроки ночи 06.11 (обязательные к соблюдению)
- **НИКОГДА не открывать лидерборд (TAB)** — правило от пользователя: тебя убивают, лишний экран не нужен.
- Смерти персонажа прогресс НЕ теряют (сила серверная) — не паниковать от смертей в брейлах.
- **Roblox GDK игнорирует синтетический ввод (SendInput/mouse_event/PostMessage) после телепортов между местами** — мышь умирает, клавиатура частично живёт. Диагноз: WindowFromPoint за пределами x>1280 возвращает hwnd=0 (окно DPI-виртуализовано: поверхность 1280x720 растянута визуально, но область кликов НЕ растянута). Лечение: полный перезапуск Roblox (Store-приложение "Roblox" → shell:AppsFolder) — но приложение тоже игнорирует синтетический ввод → нужен человек для нажатия Play. Агент умеет ждать игру (waiting mode) и подхватывает её сам.
- Auto Lift может включаться/выключаться сам (геймпасс возможно уже куплен) — бот его не трогает (whitelist); трать робуксов зафиксировано не было (диалогов покупки не появлялось).
- Джейл: OCR-фоллбек с фейковой линией (0,0) вызывал слепые клики в угол — фоллбек теперь возвращает пустоту.

## 9. Уроки утра 06.11 (продолжение)
- На больших силах (56M+) бейдж показывает шаг 0.1M: прирост подхода (~0.02M) НЕВИДИМ на бейдже -> smart_lift работает вслепую (ловушка предотвращается проактивно: SPACE + отход перед каждым подходом). Реальный прогресс проверять по STATS/лидерборду, не по бейджу.
- Колесо фортуны = ENCHANT PETS: бесплатный спин даёт питомцам бусты (+30% Strength и т.п.). Кнопки '+1 Spin 💎48' / '+10 Spins 💎348' стоят ГЕМЫ (валюта, покупаемая за робуксы) — ЖЁСТКО ЗАПРЕЩЕНО; жать только 'FREE SPIN!'. Если бесплатного нет — закрыть модалку.
- Модалки имеют разные позиции X-крестика — закрывать через OCR-поиск 'X', не по фиксированному ROI.
- Колесо: клик по 'spin' тексту опасен (попадёт в платную кнопку) — только 'freespin' без цифр.

## 10. Утренняя сессия 06.11 (финал)
- **Клики регистрируются даже с камерой внутри геометрии** — «застрявшая» камера НЕ мешает тренировке (+17.7K Strength попапы, бейдж 56.6M → 56.7M). Не тратить время на спасение камеры, если тренировки идут.
- Strength Multiplier растёт от НЕПРЕРЫВНОЙ тренировки (1.25x → 1.5x за 1м) — не прерывать подходы без нужды, множитель капает.
- Конфеты капают за повторы (458 → 942 за сессию) — тренировка = двойной доход (сила + конфеты).
- Верификация подходов на больших силах: ловить попапы '+N Strength' вокруг персонажа (OCR зоны 0.30-0.70 x 0.30-0.70) — надёжнее бейджа.
- Колесо ENCHANT PETS: 'Free spin ready!' появляется когда спины накопились; жать только FREE SPIN.

## 11. Слой верификации (сессия 15.11, после аудита кода)
Принцип: **«не смог измерить» ≠ «получилось»**. Метрика, которой доверяет обучающийся
агент, должна быть либо измеренной, либо честно помеченной как неизвестная.

- `smart_lift()` возвращает три состояния: `>0` — подтверждённый прирост, `0` — подтверждённое
  отсутствие прироста (ловушка/застревание), `None` — бейдж не прочитан (повторы сделаны,
  но обучению это не доказательство). Раньше на `None` возвращался `+1`, из-за чего ловушка
  скамьи была невидима, а в `memory.json` осели фиктивные «0.2 силы/мин».
- Верифицированный успех считается отдельно: `Capability.verified_attempts/successes`,
  `CapabilityRegistry.success_rate()` берёт только измеренные попытки. Неизмеренные не
  завышают и не занижают оценку — они нейтральны (приора 0.5).
- `read_strength()` сначала читает калиброванный ROI, а если там нет чернил — **ищет бейдж
  по цвету** в верхней полосе HUD (`template_reader.locate_badges`). Дрейф окна/DPI/раскладки
  зала больше не ослепляет бота.
- Ридер глифов не угадывает: при IoU < 0.86 глиф становится `?` (а не «похожей» цифрой).
  Это ловит отсутствующий шаблон ('0' читался как 6/8/9 → «100K» превращалось в «166K»).
- Формат числа валидируется (`is_badge_number`): потерянная при сегментации цифра ('91.K')
  и десятичная без суффикса ('56.6' вместо '56.6M') отклоняются.
- Инструменты: `python diag_reader.py` (офлайн-проверка чтения на сохранённых кадрах),
  `python tools/harvest_glyphs.py [--write]` (дообучение глифов по кадрам),
  `python -m unittest -v tests.test_verification tests.test_eye` (30 офлайн-тестов).

## 12. Слой глаза и корпус кадров (сессии 15–16.11, v1.2–v1.4)
Принцип: **«нечитаемый кадр» ≠ «игровой кадр»**. Глаз обязан честно разделять
«прочитал», «частично прочитал» и «это вообще не HUD игры».

- Иконка плашки (гантель/гем) больше не попадает в строку цифр: одна сегментация
  `_segments`/`_icon_indices` используется и чтением, и обучением. Замер:
  `'?91.5K'` (0.807) → `91.5K` (0.942).
- Бинаризация адаптивная (Otsu): затемнённые модалки читаются так же, как яркий HUD.
- Гейт «это игра?»: только бейджи, найденные в текущем кадре; сохранённая
  раскладка не доказательство. Минимальный размер плашки — 6% ширины и 3% высоты.
- OCR-rescue (дорогой) запускается только при найденных бейджах.
- Замер корпуса 48 кадров: было 38/1/6/3 при 144 с → стало **39/1/0/8 при 23 с**.
  Пять бывших «нечитаемых» — домашняя страница Roblox, загрузочный экран и окно
  редактора: они никогда не были игровым кадром.
- Живых замеров прироста силы за v1.2/v1.3 **нет** (MISSING). `data/memory.json`
  `exercise_efficiency` (1 604 809/мин у hand_weights против 0.2 у pushups) —
  артефакты старого кода и доверия не заслуживают (открытый E-005).
- Живая сессия 16.11 (v1.4): игра запущена, Place ID доказан логом клиента
  (`placeid:3623096087`); сила **3.11M**, гемы **16.1M**, три кадра совпали,
  `--health` → `ok`. Прирост за минуту так и не измерен — EXP-01 требует ввода.
- Два бага закрыты по живым данным: `"00"` больше не число (сила 0 из окна
  терминала), и `modal_open` требует управляющее слово + HUD в кадре
  (было 36 из 46 кадров, стало 12 — все реальные диалоги).
